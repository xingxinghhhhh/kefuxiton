# 前端 Web 规则

本规则继承仓库根目录 `AGENTS.md`，适用于 `apps/web` 及其前端代码。

## Next.js 与组件

- 使用 App Router；Server Component 是默认选择。
- 只有需要浏览器事件、状态、Effect、实时连接或浏览器 API 的组件才能使用 `use client`。
- 不在 Client Component 中暴露模型密钥、服务端凭据或内部系统 URL。
- 页面负责组合和数据边界；可复用业务行为放在 feature hooks/services，不放在 JSX 巨型组件里。
- 所有 loading、error、not-found 和空状态必须明确设计。

推荐目录：

```text
app/                 路由、布局、页面和路由级状态
components/ui/       无业务语义的基础组件
components/features/ 客服、知识库、会话等业务组件
lib/api/             生成或封装的 API client
lib/validation/      表单和响应校验
styles/              全局样式和设计令牌
```

`components/ui` 不得依赖业务模块；业务组件不得直接拼接内部 URL，统一使用 API client；组件输入输出必须有明确 TypeScript 类型，禁止 `any`；交互文案、错误文案和 AI 状态文案集中管理。

## 数据、状态与客服交互

- 服务端数据、客户端临时交互状态、表单状态和 URL 状态分开管理。
- 缓存键必须包含业务域、用户/租户边界和资源版本，避免串数据。
- 回答来源、转人工状态、模型状态和失败原因必须来自明确字段，不能从文本猜测。
- 任何乐观更新必须有失败回滚；接管、关闭、发布和权限操作默认使用保守更新。
- 表单使用 schema 校验，错误定位到字段并提供可行动提示。
- 明确区分客户消息、AI 消息、客服消息、内部备注、系统事件和工具结果。
- 回答卡片支持来源、反馈、重试和转人工；引用不可伪造。
- 转人工后展示等待/已接入/失败状态；接管后不得继续偷偷自动回复。
- 敏感信息默认脱敏；权限不足时显示原因，不显示原始数据。

## 可访问性与前端测试

- 键盘可操作，焦点顺序合理，表单有 label，按钮有清晰文本。
- 颜色不能是唯一信息载体；错误、风险和状态同时使用文字或图标。
- 对话窗口支持长文本、引用展开、移动端窄屏和网络中断恢复。
- 组件测试关注用户行为和可见结果，不测试实现细节。
- 关键组件使用 Testing Library；API client 覆盖成功、错误、超时和权限边界；页面级 Playwright 覆盖首次提问、引用、拒答、转人工、接管和恢复；新增交互有移动端和桌面端回归场景；禁止用真实生产模型作为普通前端测试依赖。
