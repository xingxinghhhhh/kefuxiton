# N4 验收记录：受控客服队列与 Operator 接管状态闭环

## 节点目标

完成“客户请求人工 → Operator 查看队列 → 接管 → AI 保持停止自动回复 → 关闭请求”的最小完整闭环。

## 已实现

- HandoffRequest 增加 `claimed` 状态、操作者和接管时间；AuditEvent 增加脱敏的 `actorId`。
- Staff API 提供列表、详情、claim、close；权限按 `handoff:read`、`handoff:claim`、`handoff:close` 和 `conversation:read` 划分。
- 默认无正式身份适配器时拒绝 Staff API；测试模式只使用环境变量提供的测试身份。
- `/staff/handoffs` 提供最小队列、状态筛选、最近消息、接管和关闭。
- `/chat` 展示 requested/claimed/closed，并在请求存在时不生成 Agent 消息。
- 新增迁移 `0004_operator_handoff_state`，不删除 N3 历史。

## 安全验收

- 未认证 Staff 请求被拒绝。
- 客户 Bearer 请求访问 Staff API 被拒绝。
- 客户端不能设置 `claimedBy`、状态或时间戳。
- 并发 claim 通过条件更新保护；重复 claim/close 可审计且幂等。
- 关闭后仍保持 AI 抑制，未恢复任何未经批准的自动回复。
