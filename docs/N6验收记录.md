# N6 验收记录：Operator 内部会话备注与固定标签

## 节点目标

在已认领会话中，为当前 claiming Operator 提供仅内部可见的备注和固定标签；客户、AI、检索、引用链路不得读取。

## 固定假设

- 固定标签仅允许 `urgent`、`billing`、`technical`、`follow_up`。
- 备注最大长度为 2000 字符。
- 每次备注/标签写操作必须带幂等键。
- 标签采用 active/removed 状态保留历史行，不物理删除。

## 变更范围

- API：新增 Staff-only internal-context、notes、tags 查询/写入接口。
- 数据：新增 `InternalNote`、`ConversationTag` 表及索引，保留 N1–N5 数据。
- 权限：新增 `handoff:context`，仍由 Staff identity adapter 决定，未配置时 deny-by-default。
- UI：Staff claimed 卡片显示/刷新内部上下文，并支持新增备注、添加/移除固定标签。
- 安全：审计只记录对象 ID、标签、操作和幂等结果，不记录备注正文。

## 不做事项

客户可见备注、自由标签、编辑/删除备注、转派、通知、SLA、统计、外部工单、真实企业身份和任何业务写操作。

## 验收标准

1. 非 claimed、非当前 Operator、客户 Bearer 均拒绝。
2. 标签 allowlist、备注长度和幂等键均由 API 校验。
3. 重试不产生重复备注/标签事件；审计脱敏。
4. 客户消息历史和 Agent 输入不包含内部上下文。
5. 刷新 Staff 队列可恢复内部上下文。
6. 通过完整门禁及 N1–N5 回归评测。
