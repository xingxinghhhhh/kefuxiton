# 项目角色与 Codex 多角色协作章程 v0.1

## 1. 权责

- 项目负责人：用户，负责业务目标、范围、正式渠道、模型供应商、许可证、生产部署和高风险业务决策。
- 主控 Codex/总工程师：负责读取规则、拆分最小完整开发节点、调用角色、集成变更、质量门禁、最终验证和向项目负责人汇报。
- 专业角色：项目经理、产品经理、方案架构师、后端工程师、前端工程师、AI/RAG 工程师、QA 测试工程师、安全审查员。

主控 Codex 是唯一的任务拆解者、集成者和最终审查者。聊天记录不能作为唯一决策依据；有效决策必须沉淀到仓库文档或 ADR。

## 2. 角色调用

角色配置位于 `.codex/agents/`，每个角色可重复调用，不对应长期独立会话或固定 Git 分支。

- 只读角色：项目经理、产品经理、方案架构师、安全审查员。
- 受限写入角色：后端、前端、AI/RAG、QA，只能修改主控 Codex 明确分配的节点和文件边界。
- 任何角色不得提交密钥、客户数据、生产数据或未批准的外部依赖。

## 3. 开发节点与代码隔离

一个最小完整开发节点对应一条 Git 分支。只有两个或更多写入任务相互独立且确有并行收益时，才使用独立 worktree；不能按角色默认创建 worktree。角色完成后必须返回改动文件、验证命令、结果和剩余风险，由主控 Codex 集成。

## 4. 固定顺序

产品范围 → 架构与接口契约 → 实现 → 测试/评测 → 安全审查 → 主控集成与最终验证。

## 5. N0 边界

N0 只建立 Git、Codex 角色配置、基础工程入口、规则验证脚本、协作章程和首次基线提交。不创建业务接口、数据库表、模型调用、RAG 流程、登录、前端页面、生产连接或部署配置。
