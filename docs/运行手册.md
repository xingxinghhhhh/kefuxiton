# 运行手册：配置与安全预检

## 本地 synthetic/test 运行

1. 复制 `.env.example` 到本地环境文件，并按本机 PostgreSQL 调整；不得提交真实凭证。
2. 运行 `pnpm --filter @ai-agent/api db:migrate` 应用迁移。
3. 需要 Staff E2E 时使用仅限测试的 `STAFF_AUTH_MODE=test` 和合成 Token；其他本地运行保持 `STAFF_AUTH_MODE=deny`。
4. 启动前运行 `pnpm preflight`。
5. 通过后再运行 `pnpm dev`、测试或构建。

`pnpm preflight` 只验证配置格式和运行边界，不连接数据库、不迁移、不发布知识、不调用模型或外部系统。

退出码 `0` 表示通过，`1` 表示配置缺失/非法或环境禁止组合，`2` 表示预检程序自身异常；三种情况都不会打印配置值。

## 配置字段

| 字段 | 作用 | 安全边界 |
| --- | --- | --- |
| `APP_ENV` | `development`、`test` 或 `production` | production 禁止测试能力 |
| `PORT` | API 监听端口 | 1–65535 |
| `WEB_ORIGIN` | 允许的单一 Web Origin | production 必须 HTTPS |
| `DATABASE_URL` | PostgreSQL 连接 URL | 只校验结构，错误不回显值 |
| `NEXT_PUBLIC_API_BASE_URL` | Web 使用的 API base URL | 不允许用户名、密码、查询或片段 |
| `STAFF_AUTH_MODE` | `deny` 或 `test` | production 只能 deny，正式身份尚未接入 |
| `AI_AGENT_TEST_STAFF_TOKEN` | 测试身份凭证 | 仅 test 模式使用，禁止提交和输出 |
| `ALLOW_KNOWLEDGE_PUBLISH` | 受控知识发布开关 | production 必须为 `0` |

## 失败处理

预检失败时只报告 `CONFIG_MISSING`、`CONFIG_INVALID`、`CONFIG_FORBIDDEN_IN_ENV`、`CONFIG_SECRET_FORBIDDEN` 或 `CONFIG_URL_INVALID` 及字段名。API 配置失败时不监听端口；不要把完整数据库 URL、密码、Token、API Key、Prisma 原始异常或客户消息复制到日志。

## 故障排查

- `CONFIG_MISSING`：补齐 `.env.example` 中对应字段后重新运行预检。
- `CONFIG_URL_INVALID`：确认 URL 协议、主机、路径和无凭证要求；不要把密码粘贴到聊天或提交记录。
- `CONFIG_FORBIDDEN_IN_ENV`：production 下关闭测试身份或知识发布；不要通过删除校验绕过。
- API 未监听：先运行 `pnpm preflight`，再检查安全错误码；不要直接启动旧构建产物。

## 生产前未完成项

## N18 LangGraph Human-in-the-loop 实验

N18 仅在 `packages/langgraph-lab` 中运行，不提供生产 API 或 Web 入口。它使用进程内 `MemorySaver`、固定 synthetic `thread_id` 和 `Command({ resume })`，验证“转人工后暂停、人工决策后继续”的状态闭环。

运行实验门禁：

```text
pnpm test:langgraph-lab
```

暂停结果不是 `AgentResult`，而是受限的 `n18.v1` 人工审核 payload；只有恢复完成后才产生兼容的五字段结果。人工拒绝、缺失决策、非法决策、重复恢复和过期线程都必须 fail closed。实验不接入数据库、真实身份、客户数据、真实模型、LangSmith、LangGraph Server 或任何外部系统，不得把 N18 `MemorySaver` 当成生产恢复能力。

## N19 LangGraph 执行轨迹实验

N19 在同一实验包内提供显式的 N17/N18 traced runner。默认 N17 图仍无 checkpointer，默认 N18 会话仍只使用进程内 `MemorySaver`；只有调用方明确选择 traced runner 时才注入内存 `TraceRecorder`。

轨迹使用 `n19.v1` 固定结构，只记录节点生命周期、路由、暂停/恢复状态、终态摘要、固定错误码和连续序号。`TracePath` 由真实节点进入事件推导，不能把 `GraphState.path` 或完整 LangGraph 状态直接序列化。轨迹不得包含原始用户输入、完整 interrupt payload、Token、Operator 身份、提示词、隐藏策略、模型输出、数据库对象、路径或 checkpoint 信息。

同一线程恢复使用 `resume` phase；节点重放只记录该 phase 的一次进入/完成事件。重复或过期恢复在调用图前记录 `resume_rejected`，不生成新的终态事件。N19 结果是实验层 `ExecutionTrace`，不等于生产 `AuditEvent`，不写数据库，也不提供生产恢复能力。
## 运行时健康检查（N16）

API 成功启动后提供三个只读检查：

- `GET /api/v1/health`：保留的兼容响应 `{ status: "ok", service: "api" }`。
- `GET /api/v1/health/live`：只证明已启动进程能够响应，不访问数据库。
- `GET /api/v1/health/ready`：执行固定 1000ms 超时的只读 `SELECT 1`；数据库可用返回 `200`，失败返回 `503` 和脱敏 reason code。

健康响应均设置 `Cache-Control: no-store`，不需要客户或 Staff 鉴权，不返回连接串、凭据、堆栈、本地路径、客户数据或生产准入细节。数据库在启动阶段不可用时，API 按既有生命周期不监听端口；此时不存在可访问的 liveness，不能将其解释为运行中。

健康 readiness 只表示运行依赖可用，不代表 production readiness。生产准入仍以 `pnpm release:readiness --target=production` 和 API 启动前 N15 门禁为准。

本仓库当前不执行真实部署、真实模型、企业知识、正式身份或外部系统接入。正式环境必须重新确认 HTTPS、Origin、数据库 SSL、身份适配器和凭证保管方式。

## 合成发布演练与回滚（N12）

在本地 PostgreSQL 上运行：

```text
$env:DATABASE_URL='postgresql://<local-user>:<local-password>@localhost:5432/<local-db>?schema=public'
pnpm test:release-rehearsal
```

脚本会动态选择 API/Web 端口；也可通过 `REHEARSAL_API_PORT` 和 `REHEARSAL_WEB_PORT` 显式指定空闲端口。不要把密码、Token 或连接串作为命令行参数传入。演练只创建并清理唯一的 `release_rehearsal_*` schema；不得指向共享生产库。

阶段顺序固定为：输入/端口校验、schema 创建、8 个迁移一次、合成 published fixture、production preflight/build、生产形态 smoke、复用 API smoke 与 E2E、敏感信息安全摘要、N11 基线兼容回滚读取、子进程终止和 schema 清理。输出为单行 JSON，只允许阶段、状态、构建/迁移摘要、健康结果、哈希引用和错误码；不得输出 DATABASE_URL、密码、Token、客户正文、完整堆栈或本地路径。

退出码：`0` 全部通过，`1` 阶段失败，`2` 输入/配置无效，`3` 超时，`4` 子进程终止失败，`5` schema 清理失败。清理失败必须视为失败，不能继续报告成功。
