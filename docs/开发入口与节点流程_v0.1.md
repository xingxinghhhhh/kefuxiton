# 开发入口与节点流程 v0.1

## 日常入口

用户提出目标后，主控 Codex 先检查仓库状态、AGENTS.md、需求文档、当前分支和未提交变更；随后向 ChatGPT 规划对话确认当前节点的最小范围。规划结果必须写入文档或 ADR，然后才允许实现。

## 节点流程

1. 明确节点目标、范围、依赖、验收标准和不做事项。
2. 先完成产品、架构和接口契约确认。
3. 为节点建立独立 Git 分支；仅在有实际并行收益时建立 worktree。
4. 调用受限角色实现或审查，禁止多个写入角色同时修改同一文件。
5. 运行 `pnpm verify` 及节点专属检查。
6. 通过 QA 和安全门禁后，由主控 Codex 集成并提交节点报告。
7. 向项目负责人汇报完成情况、风险和唯一下一节点，等待确认。

## N0 命令

```text
pnpm verify
```

N0 完成的证据包括：Git 工作树有效且默认分支为 `main`；八个角色 TOML 字段完整；Codex 配置启用且并发上限为 4；所有规则和文档已纳入基线提交；没有业务实现或敏感数据。
