# ADR-0032：N34 合成验证收口与生产冻结

## 状态

Accepted only for synthetic/local_eval/rehearsal evidence. This decision is not production authorization, deployment approval, or a real-business release decision.

## 决策

N34 新增测试/文档内部的 `n34.v1` 最终冻结摘要，固定封存链路：

`N29 → N30 → N31 → N32 → N33 → N33-R1`

Manifest 只保留已审查节点的安全摘要、固定评测数量、readiness、production blocker 顺序和生产冻结语义。它不保存原始日志、客户内容、Prompt、Token、连接串、绝对路径、Schema 名称、端口、环境值、堆栈或运行时对象，也不进入生产审计存储。

根字段顺序固定为：

`schemaVersion evidenceType nodeOrder expectedNodeCount items readiness productionBlockers productionFreeze syntheticOnly productionIntegration manifestDigest`

Item 字段顺序固定为：

`nodeId evidenceKind acceptanceStatus evalCount rehearsalRuns evidenceDigest`

`evidenceDigest` 是对应最小安全摘要对象的紧凑 UTF-8 JSON 小写 SHA-256；`manifestDigest` 是排除自身后的完整 manifest 紧凑 UTF-8 JSON 小写 SHA-256。两者均不排序、去重或使用运行时对象序列化。

所有 item 固定 `acceptanceStatus=ACCEPTED`、`productionReadiness=NOT_READY`、`productionIntegration=false` 的安全语义；后两项只进入 evidence digest 的受控摘要，不新增 manifest 字段。N29–N33 的 `securityScope` 为 `synthetic_only`，N33-R1 为 `rehearsal_only`。

N33-R1 只保留三次 rehearsal 的安全结论：`rehearsalRuns=3`、API smoke 清理通过、同 Schema E2E 通过且为 3 个用例、rollback/schema/worktree 清理通过。不得把运行日志、路径、端口或连接信息写入冻结证据。

## 文件边界

仅允许修改：

- `tests/evals/n34-freeze-manifest.json`
- `tests/evals/run-n34-eval.mjs`
- 本 ADR、`docs/N34-acceptance.md` 和 `docs/运行手册.md`
- 根 `package.json`：仅接入 N34 eval

不得修改 N29–N33-R1 原始 manifest、评测、生产源码、readiness evaluator、API、Web、数据库、权限、依赖、锁文件或正式准入信息。

## 固定评测与输出

N34 固定 18 条评测：节点链与六项摘要 7 条、readiness 3 条、blocker 顺序 1 条、生产冻结/未授权 2 条、R1 三次 rehearsal 与安全摘要 2 条、manifest exact-key/digest 2 条、敏感字段禁止 1 条。

评测成功只输出 `caseId`、`status`、`reasonCode`，成功 reason code 固定为 `NONE`。评测失败只允许固定安全失败码，不回显路径、输入、命令输出、异常、堆栈或环境值。

## 生产边界、验证与回滚

N34 固定 `local_eval=LOCAL_EVAL_READY`、`rehearsal=REHEARSAL_READY`、`production=NOT_READY`；生产冻结状态为 `FROZEN`，授权为 `NOT_GRANTED`，真实输入为 `NOT_AVAILABLE`。既有六个 production blocker 及顺序不变。

完整验证必须包含 N34 eval、统一历史评测、lint、typecheck、unit、integration、E2E、build、verify、API smoke、三次连续 release rehearsal、三种 readiness 和 `git diff --check`。每次 rehearsal 必须通过 API smoke cleanup、同 Schema E2E 3/3、rollback validation、schema cleanup 和 baseline worktree cleanup。

回滚点为 `dda673b`。失败时只移除 N34 manifest、评测、文档和 package script 接入，不执行 `reset`、`clean` 或覆盖其他修改。

明确排除真实模型、企业知识、Staff Identity、部署、外部系统、生产授权、持久化证据库以及任何 API/Web/数据库/权限/依赖变更。
