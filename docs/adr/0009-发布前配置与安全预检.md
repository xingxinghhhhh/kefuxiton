# ADR-0009：发布前配置与安全预检

## 状态

已批准，适用于 N11；不代表已批准真实生产部署。

## 背景

N1–N10 的业务闭环已具备，但 API、Web、Staff 测试身份和知识发布开关仍由多个入口读取环境变量。配置缺失、格式错误或把测试能力带入生产时，原有启动流程没有统一、可重复、可脱敏的阻断证据。

## 决策

- 新增内部 `packages/config`，只使用现有 TypeScript，不新增第三方依赖。
- 统一校验 `APP_ENV`、`PORT`、`WEB_ORIGIN`、`DATABASE_URL`、`NEXT_PUBLIC_API_BASE_URL`、`STAFF_AUTH_MODE` 和 `ALLOW_KNOWLEDGE_PUBLISH`。
- `pnpm preflight` 只做配置和静态边界验证，不迁移、不写数据库、不发布知识、不访问外部系统。
- API 在 Nest 创建和监听端口前加载 API 配置；失败时返回非零退出并不监听端口。
- production 禁止测试 Staff 身份、测试 Token、测试 Staff 标识和知识发布开关；未配置正式身份时继续 deny-by-default。
- Web 只接受无凭证的公开 API base URL；production 构建要求 HTTPS origin/base URL。
- 错误只输出错误码和字段名，不输出配置值、连接串、Token、API Key 或客户数据。

## 运行模式

`development` 和 `test` 允许本地 synthetic 配置；`production` 只允许正式安全边界。运行时 API 为本地开发保留安全默认值，但严格 `preflight` 要求关键字段显式存在。

## 兼容性与回滚

不改变公共 API、数据库 schema、消息、知识状态、接管、回复、审计或反馈数据。回滚目标为 N10 提交 `98f0ade`；删除预检入口不会删除数据。预检异常时不得以打印完整配置或原始连接异常的方式降级。

## 未决事项

正式部署前仍需负责人确认 production HTTPS、正式 Web Origin、数据库 SSL、统一错误码文档归属和正式 Staff 身份适配器；这些不阻塞 synthetic/local_eval N11 实现。
