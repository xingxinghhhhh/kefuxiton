# ADR-0033：N35 合成知识包三态导入与检索隔离

## 状态

已接受；仅用于 `local_eval` 和 `rehearsal` 的合成验证，不构成生产准入。

## 决策

N35 使用仓库内既有的两个合成业务包和 Markdown fixture，验证三种运行态：

1. `local_eval` 可以导入，但状态不是 `published`，因此不会进入正式检索路径。
2. `rehearsal` 只能导入到唯一命名的隔离 PostgreSQL Schema；发布版本必须通过 sourceId、sourceRef、sourceStatus、版本和仓库重算的内容哈希校验，并由 API 验证回答、引用、未知问题安全兜底和提示词注入边界。
3. `production` 在 readiness 和发布门禁处拒绝，拒绝发生在 Prisma 初始化/数据库写入和 API 监听之前。

知识内容哈希和业务包 canonical 哈希均由测试运行时重新计算，manifest 中的值只作为受校验输入，禁止手工伪造摘要。Smoke 输出只包含固定 caseId、状态和错误码，不输出连接串、路径、Token、客户原文或堆栈。

## 范围与不做事项

本节点只新增 `tests/smoke`、`tests/evals` 和 N35 文档入口；不新增模型、迁移、API、权限、UI、依赖，也不修改知识导入器、readiness、生产 Agent 或 N29–N34 文件。生产仍保持 `NOT_READY`。

## 回滚

删除 N35 新增 smoke、eval、ADR、验收记录和运行手册条目，移除 root `package.json` 中的 N35 eval 入口，回退到 `6d4fa52`。清理由测试 finally 负责，目标仅为本次生成的 `n35_synthetic_modes_*` Schema。
