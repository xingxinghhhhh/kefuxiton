# ADR-0021：N23 非生产多 Case 证据包完整性校验

## 状态

已接受。N23 是独立的离线实验节点，不代表持久化证据库或生产审计服务。

## 决策

将 N20 固定 allowlist 中的 13 个业务 replay case 对应的有效 `n22.v1 EvidenceEnvelope`，组织为纯内存的 `n23.v1 EvidenceBundle`。包只保存 `caseId` 和 `evidenceDigest`，完整 envelope 仅作为调用方提供的内存输入参与生成和验证，不进入包级输出。

`EvidenceBundle` 使用固定字段顺序：`schemaVersion`、`bundleType`、`sourceSchemaVersion`、`digestAlgorithm`、`caseCount`、`items`、`bundleDigest`。items 必须按既有 N20 allowlist 顺序排列，包级 digest 覆盖去除 `bundleDigest` 后的固定字段对象，以紧凑 JSON、UTF-8 和小写 SHA-256 计算，canonical bundle 限制为 8 KiB。

生成和验证均复用 N22 envelope 验证，检查 case 归属、source version、digest algorithm、缺失、重复、顺序和 envelope/item digest 一致性。验证失败只返回固定 schema、状态、reason code、bundle digest 匹配状态和已验证数量，不返回报告正文、输入、运行时对象或原始异常。

## 范围与不做事项

- 只修改 `packages/langgraph-lab` 实验代码、固定离线评测、文档和根测试脚本。
- 不修改 N19/N20/N21/N22 契约，不改变 N17/N18 默认行为。
- 不写文件、不访问数据库、网络、真实模型或生产模块，不重新执行 replay，不读取 fixture，不创建 `MemorySaver`。
- 不实现 API、Web UI、持久化证据服务、监控、告警或多租户能力。

## 验证与回滚

固定 N23 评测包含 13 条：1 条合法完整包和 12 条缺失、重复、顺序、未知 case、caseId、版本、算法、envelope 篡改、digest 篡改、包 digest、字段和大小边界失败场景。回滚点为 `824d11a`；回滚只移除 N23 代码、测试、评测和文档，无数据或迁移回滚。
