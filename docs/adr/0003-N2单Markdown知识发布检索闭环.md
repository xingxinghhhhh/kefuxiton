# ADR-0003：N2 单 Markdown 知识发布、检索、引用与保守拒答

状态：实现中，待 ChatGPT 审核

## 决策

N2 只实现一个脱敏 Markdown 文档的版本化存储、受控状态校验、确定性切片、确定性检索、真实引用和安全拒答闭环。检索层只读取 `published` 且处于生效期的版本；`draft`、`superseded`、`expired` 和 `local_eval` 不得参与正式回答。

当前业务材料只有候选方向，责任人、来源、版本、生效时间和哈希尚未确认。因此仓库只保存明确标记为 `local_eval` 的合成 fixture，不把它当成企业制度，也不自动发布。

## 数据与发布

- `KnowledgeDocument` 表示逻辑来源，`sourceId` 唯一。
- `KnowledgeVersion` 保存不可变版本、状态、来源引用、审核元数据、原文和内容 SHA-256。
- `KnowledgeChunk` 保存稳定序号、FAQ 字段、切片哈希和来源定位。
- 发布前必须具备 `sourceStatus=published`、来源引用、生效时间、责任人、确认时间和内容哈希。
- 新发布版本会将同一逻辑文档的旧发布版本标记为 `superseded`，不删除历史数据。
- 生产无有效发布版本时保持 N1 的安全 Mock 拒答；不硬编码候选企业事实。

## 确定性规则

Markdown 使用固定 front matter 和编号 FAQ 区块。统一 UTF-8、换行和行尾空格；每个 FAQ 至少包含问题、答案、适用条件和例外。切片上限为 1200 个 Unicode 字符，不重叠，稳定序号和 SHA-256。

检索统一 Unicode/空白和小写；英文数字按词提取，中文按相邻双字符提取。按命中比例、命中数、来源定位固定排序，阈值为 0.2，最多返回 3 个切片。无命中不使用常识补全。

## 安全边界

用户提示词注入、高风险权限/密码/生产/安全操作和敏感数据请求在检索前拒答或建议转人工；引用只能指向实际发布切片。知识正文中的“忽略规则”等内容视为不可信数据，不得驱动越权行为。

## 回滚

可将应用回滚到 N1 验收提交 `d2e2f2c`。新增知识表保留，错误版本标记为 `superseded`，恢复上一版发布知识；不删除数据库或覆盖历史版本。
