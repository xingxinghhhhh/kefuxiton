# ADR 0008：N8 Operator 结构化关闭结果

## 状态

Accepted for synthetic/local_eval implementation; formal business policy confirmation pending.

## 决策

在现有 `POST /api/v1/staff/handoff-requests/:requestId/close` 上增加结构化关闭结果：

- `closeReason`：`operator_completed`、`customer_requested_close`、`duplicate_request`、`out_of_scope`、`unable_to_resolve`
- `resolutionCode`：`resolved`、`partially_resolved`、`unresolved`、`no_action_required`

上述值及 Staff 页面中文显示名称仅是合成开发规则，不代表正式企业制度，也不得写入正式生产知识。新客户端必须同时提交两个字段；完全缺少两个字段的旧客户端使用技术兼容值 `legacy_unclassified`。只缺少一个字段或提交未知值时拒绝。

`HandoffRequest` 增加可空 `closeReason` 和 `resolutionCode`。历史已关闭记录保持 `null`，不批量回填。已关闭请求重放返回首次保存的结果；不同结果不得覆盖历史并返回冲突。仅当前 `claimedBy` 且拥有 `handoff:close` 的 Operator 可关闭或重放关闭。

首次关闭继续写 `handoff_closed` 审计事件，metadata 只包含关联 ID 和两个固定枚举值。Staff 时间线仅投影固定枚举，不返回原始 metadata；客户接口、客户页面、AI、检索和 Prompt 链路不可见。关闭后继续抑制自动 AI 回复。

## 回滚与降级

代码回滚目标为 N7 提交 `5b2ca77`。迁移字段保持可空，回滚代码不删除字段、历史数据或审计。若新结果处理失败，返回明确错误并保持现有状态，不猜测业务原因。

## 待业务确认

正式上线前需确认枚举、中文显示名称、旧客户端兼容策略和历史 `null` 方案。确认前只允许 synthetic/local_eval 测试和本地演示。
