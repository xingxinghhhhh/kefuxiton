# AI 智能客服 Agent 产品说明书

文档状态：产品设计草案（Draft）  
版本：v0.1  
日期：2026-08-07  
产品代号：CS-Agent

## 1. 产品定位

面向企业客服场景的“知识可信、遇险转人工、过程可追溯”的 AI 客服协作系统。

它不是只追求拟人化的聊天机器人，不是默认拥有企业所有权限的自主员工，也不是未经业务验证即可上线的通用大模型套壳。

## 2. 产品原则

事实优先于流畅；人工可接管；权限先于能力；来源可解释；小范围先跑通；质量可回归；产品拥有边界。

## 3. 用户与核心旅程

客户在 Web Chat 提问，系统检索已发布知识并给出回答、引用或补充问题；客户可以反馈或转人工。客服在工作台看到原话、AI 摘要、引用、工具结果和风险标签，接管、回复、备注、升级或关闭。知识管理员上传/录入、解析切片、测试、审核、发布、监控引用和负反馈、停用或回滚。质检抽查回答、标记错误并形成评测集；运营查看趋势和人工接管原因。

## 4. MVP 范围

Web Chat；单一业务领域知识库；文档导入、切片预览、审核、发布、回滚；知识回答和引用；不确定性拒答；客户主动和 AI 触发转人工；客服会话列表、接管、标签、内部备注；单条回答反馈；模型、提示词、知识、检索版本记录；基础指标、审计和离线评测。

首期不包含电话/语音、多渠道适配、自动退款/改订单/删数据、全企业跨域搜索、复杂长期记忆、模型替代审批和高风险行业专业判断。

## 5. 信息架构

```text
客户端：对话窗口、引用与反馈、转人工状态
客服工作台：待处理、我的会话、全部会话、质检标注
知识运营：知识库、文档与版本、测试问题、发布与回滚
Agent 配置：模型、提示词、检索策略、工具白名单、转人工策略
运营与治理：指标看板、审计日志、权限与角色、版本发布
```

## 6. 页面要求

客户对话必须有 AI 身份说明、输入、发送状态、回答、引用、反馈、转人工和异常提示；回答卡片按结论、条件/步骤、来源、是否解决、转人工/补充信息组织，不能展示复杂内部推理。

客服工作台为会话队列、消息时间线和客户/摘要/引用/工具/风险/内部备注区；必须区分客户消息、AI 建议、已发送内容、内部备注、系统事件和工具结果。

知识库至少显示名称、业务域、负责人、版本、状态、更新时间、有效期、引用次数和负反馈关联数；详情支持原文、解析文本、切片、元数据、版本差异、发布、停用、回滚和测试问题。

测试支持单条试问和批量评测，展示回答、引用、转人工、耗时、模型版本、检索版本和人工标注。测试集覆盖标准、边界、越权、注入、知识过期和接口异常。

## 7. Agent 行为

```text
收到问题
  -> 超出范围？是：说明范围并转人工
  -> 敏感/高风险？是：转人工
  -> 需要业务状态？是：调用只读工具
  -> 否：检索已发布知识
  -> 结果可靠？否：拒答或转人工；是：回答并展示依据
```

转人工触发器包括客户明确要求人工、连续两轮未解决、无有效检索、规则冲突、投诉/退款争议/账户安全/隐私、高风险工具失败和情绪明显恶化。首期工具只开放查询类能力；写操作必须经过方案、二次确认、人工审批、执行记录和失败补救。

## 8. 质量与发布门禁

质量维度包括正确性、依据性、完整性、安全性、可用性、稳定性和体验。知识、模型、提示词、检索参数和工具变更必须有变更说明、离线评测、高风险测试、内部试点、业务抽检、监控窗口和回滚预案。

## 9. 技术产品边界与路线

产品层不绑定模型或向量数据库。保留 `ChannelAdapter`、`ConversationService`、`AgentOrchestrator`、`KnowledgeService`、`RetrievalService`、`ToolAdapter`、`HandoffService`、`PolicyGuard`、`EvaluationService`、`AuditService` 等抽象。

V0 是技术验证：用 30–50 条脱敏样本比较 2–3 个开源方案，不接生产数据和高风险写操作。V1 是单领域 MVP；V2 增加只读订单/物流/工单和运营增强；V3 再做多渠道、语音/多模态和受审批写操作。

## 10. 必须先确定

首个业务领域、首期渠道、是否已有客服工作台、是否允许外部模型、首期知识源与负责人、是否需要只读查询、MVP 是 Demo/试点/生产。通过 Spike 后再冻结技术选型和正式架构，不提前开发多渠道、支付、自动写操作或复杂多 Agent。
